WMS Implementation Patterns

A guide to how Savant blueprints work, what decisions matter, and how to navigate a real implementation — using a manufacturing customer as the case study.

How to use this guide: This document walks through a real Savant WMS blueprint for a multi-site manufacturer. Company details have been retained for learning purposes — this is an internal training tool. Each section explains what was decided, why it matters, and what patterns you'll see repeated across other customers. Bookmark this and reference it during your first implementations.

Chapter 1

Multi-Site Architecture — The Foundation

Nearly every Savant implementation starts with understanding the customer's physical warehouse layout and how it maps to their ERP. This is the single most important thing to get right early, because every downstream decision (putaway rules, transfer logic, pick routing) builds on this foundation.

Key Pattern: Phased Rollout

Most multi-site customers start with a single pilot site. In this case, the customer has four warehouses but Phase 1 targets only one — the final assembly site (TUL2). This is typical because:

  • It reduces risk by limiting the blast radius of go-live issues
  • It creates a "Phase 1 mixed environment" where some sites run WMS and others don't
  • You need to plan for both WMS→Non-WMS and Non-WMS→WMS transfer paths
Key Pattern: Summary Locations

When Savant manages bin-level detail, Acumatica only needs "umbrella" locations. The standard approach is two summary locations per site:

  • WMS — All sellable inventory (Savant manages the bins underneath)
  • QUARANTINE — Non-sellable inventory awaiting inspection

This prevents duplicate bin management and keeps Acumatica clean while Savant handles the physical reality.

Real-World Example: Crusoe's Layout

Crusoe has four sites, but the physical reality is more nuanced. Arvada has two adjacent buildings (South Shop + North Shop) that function as one Acumatica warehouse. Tulsa has two facilities 15 minutes apart modeled as separate warehouses. Understanding this physical-vs-system distinction is something you'll encounter constantly. Always ask: "How many Acumatica warehouses does this map to?"

New Hire Takeaway
Before your first discovery call, get the site list, understand which sites are in scope for Phase 1, and map the physical layout to the Acumatica warehouse structure. Draw it out.
Chapter 2

Inventory Configuration — What Drives Everything Else

Inventory configuration is where you discover the customer's complexity. How they identify items, whether they track serials or lots, how they convert units, and how they label pallets — all of this shapes how Savant gets configured.

Key Pattern: Acumatica as Master

Savant always syncs from Acumatica for item master data. You're not creating items in Savant — you're configuring how Savant reads and uses what's already in the ERP. Key mapping points:

  • Inventory ID and description
  • Manufacturer Part Number (can live in Attributes or Cross References — ask which is primary)
  • UOM definitions and conversion rates
  • Product Attributes (zone assignments for putaway, manufacturer info)
Key Pattern: License Plates (LPs)

LPs are a core Savant concept. They consolidate multiple items under a single scannable identifier — typically representing a physical pallet. Benefits:

  • One scan moves an entire pallet (receiving, putaway, picking)
  • Track item + quantity + location in one place
  • Pre-kitting: group production materials into LP carts before issuing

Not every customer uses LPs the same way. Some assign LPs at receiving, some during production kitting, some both. Clarify this during discovery.

Real-World Decision: Wire by the Spool

Crusoe uses wire spools that could theoretically get individual LPs. The team discussed it and decided: no LP per spool, manage wire in feet only. This is a common simplification — when the tracking overhead exceeds the operational benefit, skip it. But document the decision so it doesn't come back as a question during go-live.

New Hire Takeaway
Every blueprint has an "Item Tracking Rules" section. Pay attention to what's not tracked as much as what is. No serial/lot tracking simplifies a lot of downstream processes. If it's Phase 1 "not yet," note it — it'll come up in Phase 2 conversations.
Chapter 3

Receiving — Where WMS Value Starts

Receiving is often where customers feel the most immediate WMS impact. They go from manually creating labels and keying data to scanning PO numbers and having Savant validate, capture, and push everything back to Acumatica automatically.

Key Pattern: The Standard Receiving Flow

Almost every Savant receiving implementation follows this sequence:

  • PO exists in Acumatica → operator enters PO# in Savant Mobile
  • Scan and capture data pallet by pallet (items, quantities, LP assignment)
  • Savant pushes receipt confirmation back to Acumatica (synchronized document)

Variations to watch for: Does the customer allow under-receiving? Over-receiving? Can they receive items not on the PO? These are configuration switches, not customizations.

Key Pattern: QMS Integration

Customers using external quality management systems (QMS) add a hold/release layer. Items are received but marked as unavailable until QMS approves. The integration typically works via push notifications between Acumatica and Savant. This is a common addendum — be prepared to scope it.

Real-World Detail: Attachments Stay in Acumatica

Crusoe uploads heat numbers, inspection results, and supplier certifications as file attachments on PO line items. These stay in Acumatica — Savant doesn't manage them. This is worth noting because customers sometimes assume "WMS" means "everything." Set expectations early: Savant handles physical inventory execution; document management stays in the ERP.

Chapter 4

Production — The MFG/WIP Module

This is the most complex area for manufacturing customers. Savant becomes the execution layer while Acumatica remains the system of record. The key phrase to remember: barcode-driven and operation-based.

Key Pattern: Work Center Pick Tickets

Instead of one giant pick list per manufacturing order, Savant splits picks by work center/operation. Fabrication gets its material picks. Paint gets its picks. Electrical gets its picks. This matches how the warehouse actually operates — people work in zones, not across entire BOMs.

Key Pattern: Change Requests and Cancellations

Every blueprint has items that were initially discussed as custom change requests but later cancelled. These are important to document because:

  • They show the customer what standard functionality covers
  • They prevent "we thought we were getting X" conversations later
  • They often resurface in Phase 2 scoping
Real-World Cancellations

Crusoe originally requested two custom features:

  • Partial MO Picking — build 2 of 10 with proportional picks. Cancelled: standard functionality covers this.
  • "Issue When Required" confirmation screen — a controlled issue step. Cancelled: standard Savant issue process used instead.

Both were resolved by demonstrating that standard Savant handled the use case. This is why thorough demo prep matters — you can save the customer (and your team) weeks of custom dev work.

New Hire Takeaway
When a customer says "we need custom X," your first response should be "let me show you how standard handles that." Cancelled CRs are wins — they reduce scope, cost, and timeline. Track them explicitly.
Chapter 5

Order Fulfillment — Ship and Confirm

For manufacturing customers, outbound volume is typically much lower than distribution or 3PL customers. But the process still matters — it's the last touch before the customer's customer sees the product.

Key Pattern: Low-Volume / High-Value Fulfillment

When a customer ships 6–10 orders per week (not per hour), the configuration is simpler:

  • Paper pick tickets instead of pick labels or wave/batch picking
  • Manual release instead of automated wave planning
  • No QC/Packing module needed
  • Standard packing lists and ship confirmation

Don't over-engineer fulfillment for a customer that ships 30 orders a week. Match the solution to the volume.

Real-World Volume Profile
HQ (Arvada) 5–6 shipments/week Fabrication 4 internal transfers/week to assembly site Assembly (TUL2) 6–10 outbound shipments/week (increasing) QC/Packing Not used Returns Not applicable (high-value equipment)
Chapter 6

Addendums — Where the Real Complexity Lives

The main blueprint body describes standard and configured functionality. Addendums are where customizations, extended configurations, and edge-case workflows get documented. They're separate documents for a reason — they go through their own review and approval cycle.

The Three Types
  • Customizations — New functionality that doesn't exist in standard Savant. Requires development. Examples: QMS push notification integration, outside process vendor shipment handling.
  • Extended Configurations — Functionality that exists in Savant but needs significant configuration or workflow design. Examples: picking by work center, backflushed materials.
  • Phase 2 Items — Acknowledged requirements deferred to a future phase. Example: labor tracking via kiosks.
Crusoe's Addendum Inventory
001 QMS Integration (Customization) 002 Picking by Work Center (Extended Config) 003 Backflushed Materials (Extended Config) 004 Outside Process Vendor Shipment (Customization) 005 Production Order Moves (Extended Config) 006 Inventory Transfers Non-WMS ↔ WMS (Customization)
New Hire Takeaway
Always read the addendums before an onboarding call. The main blueprint gives you the "what." The addendums give you the "how" for everything that isn't standard. If a customer asks about a process and you don't know the answer, check the addendums before escalating.
Chapter 7

Blueprint Anatomy — What to Look For

Every Savant blueprint follows the same general structure. Knowing the structure means you can navigate any customer's blueprint quickly, even if you've never seen it before.

Standard Blueprint Sections
1. Administration Sites, branches, zones, locations, security. The physical/logical foundation. 2. Inventory Item master, UOM, tracking rules, putaway, replenishment, labeling, counts, adjustments, transfers. 3. Receiving PO receipt flow, QMS integration, putaway, vendor returns. 4. Production MO flow, pick management, material movement, outsourced production, labor. 5. Fulfillment Pick routing, packing, ship confirmation. 6. Returns Customer return process (if applicable). 7. Reports Standard vs. custom reporting. 8. Addendums Customizations and extended configurations.
Color Coding in Blueprint Documents
  • Yellow highlights: Items needing more information, research, or discussion
  • Blue highlights: Customizations or added configurations beyond standard out-of-the-box
  • Green highlights: Recently updated content (version changes)

When you see yellow in a blueprint, that's an open item. If it's still yellow at sign-off, someone missed something. Make it your job to close yellows.

New Hire Takeaway
Read one complete blueprint end to end before you attend your first implementation kickoff. Then read a second one from a different customer. By the third, you'll start seeing the patterns — and the patterns are what make you effective, not memorizing individual customer details.
